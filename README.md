# Ukraine Medical Admissions

Independent admissions-support business and website for international students applying to medical universities in Ukraine. Production domain: https://ukrainemedicaladmissions.com/

| Folder / file | Purpose |
|---|---|
| `site/` | The website (Astro, static output + PHP enquiry handler). `npm install && npm run dev` to work locally; `npm test` builds and runs all checks. |
| `site/scripts/` | First-write tooling (no network, nothing touches the server): `npm run manifest` (every file a deploy writes, with SHA-256 and a release fingerprint) and `npm run compare:backup -- <extracted-backup-dir>` (legacy URL inventory, KEPT/REDIRECTED/UNCOVERED coverage, proposed redirects, collisions, untouched files). See `HOSTING_AND_DEPLOYMENT_ASSESSMENT.md` §11. |
| `site/tests/` | Checks run by `npm test` and CI: record schema + evidence invariants (`test:records`), links, metadata (incl. JSON-LD validity and `security.txt` expiry), redirect safety, UI smoke, accessibility, Lighthouse budgets, tooling self-test, staging guard, publication gate over the production and preview builds (`test:gate`), preview UI + axe over every draft record (`test:preview`). |
| `site/src/content/universities/` | **Single source of truth** for university and programme data (schema: `site/src/content/schema.mjs`). Every fact carries a verification status, source URL and check date. A record with `verification.publishable: false` produces **no page in production**; review drafts locally with `npm run build:preview` (output `dist-preview/`, noindex, never deployed). `site/src/content/samples/` holds the synthetic sample used only under `/preview/`. |
| `brand/` | Logo, favicon, brand guidelines, homepage design direction. |
| `*.md` at root | Project records. Start with `PROJECT_EXECUTION_PLAN.md` (decisions, Phase E proposal), then `BASELINE_REPORT.md` (verified current state), `KEYWORD_URL_MAP.md` (SEMrush evidence, country comparison, master keyword-to-URL register, money-page register, costed research request), `UNIVERSITY_DATA_REGISTER.md` and `PROGRAMME_SUPPLY_REGISTER.md` (what may be presented and what is unverified), `DIRECTORY_VERIFICATION_PLAN.md` (per-record status and the route from draft shells to verified profiles), `APPLICATION_SYSTEM_SPEC.md` (candidate-profile and readiness service), `SERVICE_TIERS_SPEC.md` (revenue options), `VISUAL_AUDIT_AND_IMAGE_REGISTER.md`, `HOSTING_AND_DEPLOYMENT_ASSESSMENT.md`, `SECURITY_AND_RELEASE_CHECKLIST.md`, `SEMRUSH_API_LEDGER.md`, `SOURCE_VERIFICATION_REGISTER.md`, `TECHNICAL_REPAIR_BACKLOG.md`. Analytics and Search Console plan: `ANALYTICS_AND_SEARCH_CONSOLE.md`; Stage-2 design: `APPLICATION_SYSTEM_SPEC.md` §14; latest handover: `EXECUTIVE_REPORT.md` §N. |
| `.github/workflows/` | CI (build + tests on every push) and the manual production-branch publisher. |

Rules that never change: no invented university facts; no WhatsApp CTAs; the primary CTA is **Apply Online Now**; nothing reaches production without the release checklist and the owner's approval.
