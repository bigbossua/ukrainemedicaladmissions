# research/verification — evidence registers for manual verification

One folder per university record that has a register: the three records whose verification has been approved (2026-10-11: Vinnytsia, Odesa, Bukovinian) and the five research drafts added the same day (Kharkiv, Zaporizhzhia, Dnipro, Lviv, Poltava; registers prepared for later verification, not approved for it yet). Each `EVIDENCE_REGISTER.md` is generated from two files — the record JSON (`site/src/content/universities/<slug>.json`) and its evidence file (`site/data/evidence/<slug>.json`) — and lists, row by row, every claim the published profile would show: the claim path (the same `claimPath` an evidence entry uses), its current status, the unverified lead (if any), the official page(s) to open, what to read and record, the evidence entries recorded for that claim (status, source tier, date accessed, quotation present yes/no, publish / withhold decision — or "no evidence recorded"), and empty columns for the capture file name, the verified value or wording and the date read. An **Access** line near the top repeats the evidence file's access block, and section H checks the evidence file's structure and flags any entry whose claim path matches no row.

The rules — the evidence file format, the six statuses, the source tiers each claim type needs, conflicts, `nextReview` and the step-by-step procedure for one claim — are in `UNIVERSITY_EVIDENCE_STANDARD.md` at the repository root.

**Nothing in these registers is verified.** Every evidence file holds `"entries": []`. As of 2026-10-11 every official host is unreachable from the build environment: the first attempt failed at DNS for both `curl` and the fetch tool, and the second session's `curl` test (18:18 UTC) was refused at the environment's proxy (`CONNECT tunnel failed, response 403`; HTTP code 000) for every university, Ministry, NAQA, archive and directory host — see `SOURCE_VERIFICATION_REGISTER.md` and `DIRECTORY_VERIFICATION_PLAN.md` §10. The registers are therefore the precise work-list for either route:

- **Route A** — the owner allow-lists the domains (`DIRECTORY_VERIFICATION_PLAN.md` §3 and §10); Claude then opens the pages, writes an evidence entry for each claim, updates the record JSON only for entries that are verified with the decision "publish", regenerates the register and records the session in `SOURCE_VERIFICATION_REGISTER.md` (`UNIVERSITY_EVIDENCE_STANDARD.md` §11.2).
- **Route B** — the owner or daughter captures the pages (section "How to capture a page" in each register) and shares the folder; Claude (or the daughter, via GitHub) writes the evidence entries from the captures (`evidenceType` `owner-capture`, `sourceUrl` = the URL printed on the capture, `accessed` = the capture date, `captureRef` = the file name) and then updates the record JSON in the same way (`UNIVERSITY_EVIDENCE_STANDARD.md` §11.3).

Captures stay **outside the repository** while it is public (confirmed public on 2026-10-11). The register and the evidence file record only file names such as `odesa-national-medical-university--08--fees.pdf`.

A record becomes `publishable: true` only when every row of its register is either verified or closed as not-published with the page that is silent, every verified claim has a matching evidence entry with an exact quotation (`UNIVERSITY_EVIDENCE_STANDARD.md` §4), its open questions are empty, `lastReview` is set, and `npm test` passes (`test:records` rules R1–R9, `test:gate`, `test:preview`). The automatic cross-check between record claims and evidence entries belongs to the publication-policy code, which another work package owns; until it exists the reviewer checks it by hand with the register's evidence column. Deferred programmes (`deferredProgrammes[]`) are never published until an official page states that international applicants are admitted.

Regenerate a register after the record JSON or the evidence file changes (from the repository root): `python3 -I site/scripts/make-evidence-register.py <slug> [<slug> ...]`. With no slug it regenerates the three approved registers.

**Tools.** `site/scripts/capture-intake.py` checks a folder of owner captures kept outside the repository: size and SHA-256 of each file, which section A rows have a capture and which are still missing, and where a phrase appears (file and page), so a quotation can be found and then copied from the capture itself; it writes nothing into the repository. `site/scripts/evidence-entry.mjs` records one evidence entry: it checks the entry against the evidence format, refuses an unknown claim path, gives the next id and shows whether the publication policy would show the claim, and why not; it writes only with `--write`, and `--apply-to-record` updates the record claim from a verified entry with the decision "publish", so record and evidence cannot drift. `UNIVERSITY_EVIDENCE_STANDARD.md` §15 walks through one Vinnytsia tuition claim with both.

**Lead register (30 October 2026).** `LEAD_REGISTER_2026-10-30.md` (data: `lead-register-2026-10-30.json`) holds search-engine leads for all 45 records: register codes, Ukrainian names, websites, status, programmes, admissions, fees, deadlines, accreditation and the conflicts between them, each checked by an independent checker against its cited extracts and, for the decisive fields, by a fresh search. They are leads, not evidence: 0 records are verified or partially verified, 31 hold conflicting or outdated leads and 14 hold secondary-source leads only. `CAPTURE_LIST_2026-10-30.txt` lists the 481 official and register URLs to capture (Route B) to turn them into evidence. No record JSON or evidence file was changed.
